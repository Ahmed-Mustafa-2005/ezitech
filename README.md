# Brew & Bean Cafe – Task 1: Baseline Normal API Traffic

Part of the SOC Log Triage project for Ezitech. This is a local lab exercise;
all data is fake and generated by the script.

## What it does

`log_baseline.py` does two things:

1. **Generates `sample.log`** – 500 lines of normal, authorized API traffic from
   5 users (`user_101` to `user_105`). Requests are GET `/orders` (~70%) and
   POST `/orders` (~30%), nearly all with status `200`.
2. **Reads the log back and counts requests** per user, per endpoint, and per
   user + endpoint, then prints a summary table and saves it to
   `baseline_output.txt`.

## Log format

```
timestamp, user_id, method, endpoint, status_code
2026-11-17 08:01:26, user_101, GET, /orders, 200
```

## How to run

Requires Python 3.8+ (standard library only, nothing to install).

```bash
python log_baseline.py
```

Output files:

| File | Contents |
|------|----------|
| `sample.log` | The generated 500-line log |
| `baseline_output.txt` | The summary tables (same as the terminal output) |

The script uses a fixed random seed (`SEED = 42`), so you get the same log every run.
Change the seed to get different data.

## Reading the output

- **Requests per user** – how many requests each user made and their share of
  the total. In normal traffic every user is in a similar range (roughly 17–21% each).
- **Requests per endpoint** – the split between GET and POST on `/orders`.
  Normal is about 70% GET / 30% POST.
- **Requests per user and endpoint** – each user's GET/POST mix.
- **Status codes** – normal traffic is almost entirely `200`, with a very small
  number of `400` errors on POST.

This is the **baseline**. In the next tasks, requests that deviate from it
(for example unknown endpoints, other users' order IDs, or bursts of
401/403/404 responses) will stand out as suspicious.

## Task reflection

I wrote a Python script that generates a 500-line fake API log for five users, mostly GET and POST requests to `/orders`, then parses it and counts requests per user and endpoint. I saved the summary table in `baseline_output.txt` and documented how to run the script and interpret the output here. To make the traffic realistic and repeatable, I used weighted random choices (about 70% GET and 30% POST), a small number of 400 responses, and a fixed seed. I kept attack and suspicious traffic out of this baseline because that belongs in a later task.
